### Reading it

- When the store holds the one fact a task needs, ghost turns a sure failure into a pass for about 9% more cost.
  The cases were built so that only ghost holds that fact, so this is an upper bound on the benefit, not a typical session.
- The harm checks held. The stale memory pointed at `config/settings.yaml`, and the agent still edited `settings.toml` in every run.
  The unrelated changelog convention was injected into a one-line docstring task, and no run created `docs/api-changes.md`.
- Most memories that get in score below the 0.55 floor: 0.23, 0.26, 0.40, and junk at 0.00–0.02.
  The floor is not what is admitting them; rescue and edge paths are.
  The junk costs tokens without changing outcomes here.
- This sits alongside the 2026-09-23 live eval, where per-prompt injection was used about 2% of the time.
  The channel works when a relevant memory exists; the live problem is how often one does for an everyday prompt, and the noise sent when none does.

### Limits of this suite (fresh-context review)

- **The +0.56 means "a fact only ghost holds, delivered," not "ghost helps in daily use."** Every target memory is injected for its own case, with 0–3 low-score distractors. The 58 seed distractors cover unrelated topics, so nothing competes, and the must-have baselines score 0 by construction.
- **retry-decision tests injection, not the recall tool.** The hook injects `acme-retry-policy` (0.40), so the policy passed 3/3 while recall ran in only 1 of 3 runs.
- **Both harm checks contain a guard.** "Change nothing else" disarms the docstring case, and one Glob refutes the stale YAML path because `config/` holds only `settings.toml`. A harm case without a guard is still missing.
- **A failed fixture copy or ghost call turns the with-arm into the baseline without warning.** No grader checks that injection happened.

Next iteration:
- distractors on acme-api topics, so retrieval has to rank
- a harm case with no guard phrase, where the stale memory is plausible against the repo
- a case where only the recall tool can find the fact (below injection's reach)
- an injection-happened indicator

### Not verified

- N = 3 per arm; no confidence intervals.
- The fixture is synthetic (58 seed distractors plus 5 case memories). It does not reproduce the live store's size or its score distribution.
- Traces were not kept (`--keep-temp` was off), so recall use is measured only through the retry-decision indicator.

## Edge expansion A/B (2026-10-06)

Question: should edge expansion (spreading activation over memory edges) be turned off or tightened? Live session-start context was filling with edge arrivals scoring 0.00–0.01.
Knobs: `GHOST_EDGE_EXPANSION=off` and `GHOST_EDGE_MIN_SCORE` (#140, defaults unchanged).
The suite gained `deploy-prereq`: its fact is reachable only through a `refines` edge from the deploy memory. The fixture also gained a consolidated session node that `contains` the competing sibling-repo memories.

| | Edges off | Min score 0.05 | Min score 0.1 |
|---|---|---|---|
| `TestEvalReport` (retrieval) | no change | no change | no change |
| `TestEvalMultiHopReach` | **both chains fail**: the first hop never arrives | same as baseline | similarity chain loses hop 1 |
| Live replay (40 real queries, store copy): tokens/call | 1150 vs 1224 | 1200 | 1200 |
| Live replay: edge arrivals scoring <0.05 (baseline: 11) | 0 | **0** | 0 |
| Agent A/B (8 cases × 3 runs, j2): outcomes | no difference | no difference | not run |
| Agent A/B: cost | $2.18 vs $2.14 | $2.09 | — |

Decision: keep edges on and set `GHOST_EDGE_MIN_SCORE=0.05` in the prompt and session-start hooks.
It removes every near-zero passenger and loses nothing ghost's suites measure. 0.1 starts cutting legitimate similarity hops.

What the agent A/B could not show:
- **Every graded failure in an injection case was a run where injection did not fire:** 5 of 63, about 8%, even at concurrency 2 with a 180 s timeout.
  - Root cause: eval runs get a fresh HOME, so each ghost call downloaded the embedding model (~184 MB, 5–10 s), and some runs lost the injection.
  - Fixed by passing `GHOST_MODELS_DIR`: injection then fired in 22 of 22 runs.
  - Production hooks use the real HOME and its model cache, so they don't hit this.
  - Without a cached model and with no network, ghost still answers, falling back to text search, but only after about 21 s of retries.
- **`deploy-prereq` is 0/3 in every variant**, which exposed an orphan quirk. Expansion runs before the score floor. The prompt's deploy memory fell below the floor and was dropped, while the migrate memory it pulled in through the edge survived (score 0.03). The agent got "run make migrate first" without the deploy command. Fixed in #141: an edge arrival now survives the floor only if a memory that pulled it in survives.

A first run at concurrency 4, alongside the replay, was discarded: injection timed out under load, and zsh word-splitting meant one variant never ran.
Spend: about $6.40 for the clean run, about $13 including the discarded one.
